# Weights of Giants — Season Zero Starter Kit
### The Low-Energy Edge Challenge (`wog-cv-v2.1`)

Welcome to **Season Zero** of the [Weights of Giants (WOG)](https://weightsofgiants.com) hardware-in-the-loop vision arena.

This kit gives you everything you need to **train**, **wrap into the exact ONNX contract**, **configure `model.json`**, **score locally before spending a Run Token**, and **verify** your detector for the physical **Libre Computer La Frite** (`ARM Cortex-A53 @ 1.2 GHz`, `1 GB RAM`).

> **Important:** The bundled `models/detector_int8.onnx` generated by `models/create_baseline_onnx.py` is an **untrained all-zeros schema smoke-test stub** (0.0% mAP) used only to verify `verify_local.py` wiring. Replace it with a real detector before submitting.

> **Licensing Notice (Read Before Training or Exporting):**
> * **Ultralytics YOLO11 / YOLOv8 (`yolo11n.pt`, `yolov8n.pt`, etc.):** Ultralytics releases these under **AGPL-3.0** and states that trained/exported derivative models are also covered by **AGPL-3.0**. **Season Zero accepts `AGPL-3.0`**, so if you start from Ultralytics weights, you **must** license your submission repo `AGPL-3.0` — do **not** label it `MIT` or `Apache-2.0`.
> * **Want permissive `Apache-2.0` or `MIT` licensing?** Start from Apache-2.0 edge detectors like **NanoDet-Plus**, **YOLOX-Nano**, or **PP-PicoDet-S** (the same open-source architectures used for the Season Zero reference baselines below).

## 3. Exact Hardware, Frame Rate & Tensor Contract (`la-frite-1gb`)

The referee streams unmodified `480×320` RGB surveillance frames sampled at **`~2.5–6 FPS`** (not 30 FPS) to the air-gapped La Frite board, which runs your ONNX file through `onnxruntime` CPUExecutionProvider:

### Input Tensor (Automatic on Board)
* **Shape & dtype:** `[1, 3, input_h, input_w]` `float32`, **RGB** channel order (not BGR), normalized to **`[0.0, 1.0]`** (`pixel / 255.0`).
* **Resize policy (`frame_policy.resize`):**
  * `letterbox` *(recommended)*: aspect-preserving resize onto a `(114, 114, 114)` gray canvas. The board automatically unmaps your normalized box coordinates back to original frame coordinates.
  * `stretch` or `crop`: also supported.
* If your backbone expects ImageNet mean/std, `[0, 255]`, or BGR, **bake that normalization into the start of your ONNX graph**.

### Output Tensor (Must Be Inside Your `.onnx`)
* **Shape & dtype:** `[1, N, 7]` `float32` *(Mode A: board runs managed `bytetrack-lite`)*, `[1, N, 8]` *(Mode B: native `track_id >= 1`)*, or `[1, N, 6]` *(axis-aligned `[cx, cy, w, h, conf, cls]`, `theta` defaults to `0.0`)*.
* **Columns for `[1, N, 7]`:**
  1. `cx, cy, w, h`: box center & size normalized to **`[0, 1]`** relative to `[input_w, input_h]`.
  2. `theta_rad`: rotation in **radians** (Season Zero labels use canonical `[-π/4, +π/4]`, i.e., `±45°`; upright `0.0` is valid for axis-aligned models).
  3. `conf`: confidence in **`[0, 1]`** (after sigmoid/softmax). Detections below `0.10` are dropped immediately; detections `>= conf_threshold` pass class-aware rotated NMS (`iou_threshold`, capped at 100/frame) and are scored for mAP and native HOTA.
  4. `cls`: **`0` = `person`**, **`1` = `vehicle`** (car, truck, bus, motorcycle, bicycle).

> **Do NOT submit raw Ultralytics `[1, 84, 8400]` or `[1, 6, 2100]` ONNX exports directly.** Always run `export_onnx.py` so the ONNX graph outputs `[1, K, 7]` directly.

### Eligibility Gates & Scoring Weights (`wog-cv-v2.1`)
| Metric | Eligibility Floor / Cap | Full-Credit Bar | Pillar Weight |
|---|---|---|---:|
| **Detection (`mAP@50:95` above `conf_threshold`)** | `>= 25.0%` per domain | `100%` | **35%** |
| **Tracking (native HOTA)** | `>= 30.0%` per domain (`>= 50%` Genesis Lineage) | `100%` | **30%** |
| **Sustained Throughput (`>= 300 s` load, `skip: 0`)** | `>= 2.4 FPS` per domain | `>= 10.0 FPS` | **20%** |
| **Peak RAM (La Frite 1 GB)** | `<= 800 MB` | `<= 205 MB` | **10%** |
| **Robustness (11 stress passes + blank canary)** | No separate floor *(Policy B: `0` if clean mAP `< 5%`)* | `100%` | **5%** |
| **Per-Domain Composite Score** | **`>= 35.0 / 100`** per domain | `100` | — |
| **Artifact Size & ONNX Ceiling** | `<= 40 MB`, `IR <= 10`, `opset <= 22` | — | — |

*Object scale tiers:* Required targets are `>= 15 px` on stored `480×320` frames (`~10 px` on `320×320` letterboxed input). Smaller `12–15 px`, small edge-clipped, and `>= 50%` occluded targets are optional (no FP penalty, scored separately in the unweighted `far_field` diagnostic).

## 4. Step-by-Step: Train, Wrap, Configure, Score Locally & Submit

### Step 1 — Install local tools
```bash
pip install -r requirements-train.txt
# Only if training/exporting Ultralytics YOLO models (AGPL-3.0):
pip install ultralytics torch
```

### Step 2 — Prepare a 2-Class Dataset (`0=person`, `1=vehicle`)
Remap any YOLO-format 80-class COCO dataset to WOG's 2 classes:
```bash
python train.py prepare-coco \
  --src-labels datasets/coco/labels \
  --dst-labels datasets/wog_2class/labels \
  --images-dir datasets/coco/images \
  --out-yaml datasets/wog_2class/data.yaml
```

### Step 3 — Train or Choose a Starting Model
* **Permissive path (`Apache-2.0` / `MIT`):** Train or fine-tune an Apache-2.0 detector (**NanoDet-Plus**, **YOLOX-Nano**, or **PP-PicoDet-S**) and export its raw ONNX, then wrap it with `export_onnx.py --mode wrap-onnx`.
* **Ultralytics path (`AGPL-3.0` required):** Train inside the `.gitignore`d `work/runs/` folder so `.pt` checkpoints never enter git:
  ```bash
  python train.py train \
    --data datasets/wog_2class/data.yaml \
    --model yolo11n.pt \
    --imgsz 320 \
    --epochs 50 \
    --batch 32
  ```
  *(For oriented bounding boxes, pass `--model yolo11n-obb.pt --obb` with a YOLO-OBB dataset.)*

### Step 4 — Wrap & Export to the WOG `[1, K, 7]` ONNX Contract
```bash
# Custom 2-class Ultralytics checkpoint (license repo AGPL-3.0):
python export_onnx.py \
  --mode yolo \
  --weights work/runs/wog_train/weights/best.pt \
  --imgsz 320 \
  --out models/detector.onnx \
  --update-manifest

# Quick smoke test with pretrained COCO YOLO11n + INT8 quantization (license repo AGPL-3.0):
python export_onnx.py \
  --mode yolo \
  --weights work/yolo11n.pt \
  --imgsz 320 \
  --coco-remap \
  --quantize int8 \
  --out models/detector_int8.onnx \
  --update-manifest

# Wrap any existing raw YOLO-style ONNX ([1, 4+C, N] or [1, 5+C, N]) without PyTorch:
python export_onnx.py \
  --mode wrap-onnx \
  --onnx work/raw_detector.onnx \
  --imgsz 320 \
  --num-classes 2 \
  --out models/detector.onnx \
  --update-manifest
```

### Step 5 — Tune `model.json` (or `wog.yaml`)
See `examples/model_fast_320.json`, `examples/model_accurate_416.json`, and `examples/wog.yaml`:
* **`input_size`**: `[320, 320]` or `[416, 416]` — check the La Frite baseline table above before pushing to `512×512`.
* **`conf_threshold`**: Controls both detection precision/recall (`mAP@50:95` only counts detections `>= conf_threshold`) and false alarms on blank canary clips. Typical sweet spot: `0.25–0.35`.
* **`iou_threshold`**: Rotated NMS threshold (`0.45` is a solid default).
* **`tracker.params` (`~2.5–6 FPS` clip rate):** Because Season Zero surveillance clips are sampled at **2.5–6 FPS** (not 30 FPS), `track_buffer: 6` holds a lost track for **~1–2 seconds** (whereas `track_buffer: 30` would hold ghosts for 5–12 seconds!). Keep `track_thresh >= conf_threshold` (e.g. `conf_threshold: 0.30`, `track_thresh: 0.35`).

### Step 6 — Score Locally BEFORE Spending a Run Token
Run your model on the included 25-frame `@ 3.75 FPS` crosswalk dev clip (`dev_clip/`, MIT-licensed, **not** in the official Season Zero test suite) + a 10-frame blank canary check using the exact `wog-cv-v2.1` scorer:
```bash
python score_local.py --save-vis work/dev_preview.jpg
```
Then run the packaging, contract, and post-NMS single-image verifier:
```bash
python verify_local.py --image dev_clip/frames/frame_0000.jpg --save-preview work/preview.jpg
```
Both the console detection list and the saved preview image show the **exact post-NMS boxes** the La Frite board will score.

### Step 7 — Submit to the Arena
1. Add the matching `LICENSE` file (`AGPL-3.0` if derived from Ultralytics YOLO; `Apache-2.0` / `MIT` / `BSD` if derived from permissive weights) and push `model.json`, `models/*.onnx`, `README.md`, and `LICENSE` to GitHub or Hugging Face. Confirm `git status` shows **zero** `.pt`/`.pth`/`.pkl` files.
2. Sign in at [weightsofgiants.com](https://weightsofgiants.com) and click **Submit a Model** (3 free Run Tokens to start, +1/day up to 3 max).

## 5. Common Pitfalls & Quick Fixes

| Symptom | Cause | Fix |
|---|---|---|
| `Invalid output shape: (1, 84, 2100)` | Raw Ultralytics ONNX submitted without wrapping | Run `export_onnx.py --mode wrap-onnx ...` |
| `Active box coordinates look unnormalized` | Model outputs pixel coords (`0..320`) instead of `[0, 1]` | Divide `[cx, cy, w, h]` by `[W, H, W, H]` (automatic in `export_onnx.py`) |
| `Angle theta exceeds radians range` | Model outputs degrees (`-45..45`) | Convert to radians (`deg * pi / 180`) inside ONNX |
| `Forbidden unsafe artifact found: best.pt` | PyTorch checkpoint committed to git | Keep checkpoints in `work/` (`.gitignore`d) and commit only `.onnx` |
| Misdeclared license on YOLO11 model | Ultralytics weights labeled `MIT` or `Apache-2.0` | Use `AGPL-3.0` (accepted!) or switch base weights to YOLOX / NanoDet-Plus / PP-PicoDet |
| Low `score_local.py` mAP despite clean boxes | Model trained on BGR or ImageNet mean/std | Bake RGB-to-BGR / mean-std normalization into the ONNX input |
| Speed below `2.4 FPS` on La Frite | Heavy backbone or `512×512` input | Drop to `320×320`, prune channels, or apply `--quantize int8` |
